# Hardware and wiring

Hardware reference: [TomatoCube — Box 10 Bear-Buddy DIY Desk Companion](https://github.com/TomatoCube18/Docs/tree/main/Box%2010%20-%20Bear-Buddy%20DIY%20Desk%20Companion).

## Bear-Buddy pin map

| Function | ESP32-C3 pin | Notes |
|---|---:|---|
| Status LED | IO3 | Onboard LED |
| Button A | IO9 | Active low; shares the BOOT strap function |
| Button B | IO4 | Active low |
| Buzzer | IO10 | Onboard peripheral |
| NeoPixel data | IO7 | 5×5 serpentine `NEO_GRB + NEO_KHZ800` |
| IR receiver | IO21 | Idle high; carrier bursts pull low |
| I²C SDA / SWIO | IO5 | Onboard 10 kΩ pull-up; shared with the programmer link |
| I²C SCL | IO6 | Onboard 10 kΩ pull-up; not used by the SWIO bit-banger |

The Bear-Buddy already has 10 kΩ pull-ups on both I²C lines. The SDA pull-up on IO5 is sufficient for SWIO, so no external resistor or board modification is required. Do not enable I²C and SWIO simultaneously because IO5 is explicitly shared.

## SWIO connection

- ESP32 IO5 / I²C SDA → CH32V003 PD1 / SWIO.
- Use the existing onboard 10 kΩ SDA pull-up; no external pull-up is required.
- Common ground is required.
- The `R_GLITCH_HIGH` workaround remains disabled because the onboard pull-up is already present.
- SWIO transfers disable interrupts. IR reception and matrix updates are suppressed while a flash/read operation is active to avoid collecting a corrupted frame.

## Target remote pins

| Function | CH32V003 pin |
|---|---|
| SW1 | PC4 |
| SW2 | PC2 |
| SW3 | PC1 |
| SWIO | PD1 |
| IR / indicator LED output | PA2 / TIM1_CH2N |

The target output is active low. The 38 kHz carrier is generated by timer hardware; firmware only gates the timer.

## NeoPixel layout

The 25-pixel chain is serpentine:

- Even rows run right-to-left.
- Odd rows run left-to-right.
- Pixel index starts at the top-right.
- Brightness is 32 to limit USB current.
- A message scrolls once at 90 ms per column and then clears.

## Power

Use a stable USB supply. The matrix and WiFi radio can create short current peaks. Symptoms of insufficient power include random restarts, `rst:9` (brownout), or a USB port that disconnects and re-enumerates.

## UART conflict

The optional target terminal uses UART0. On ESP32-C3, UART0 defaults to IO20/IO21. Enabling it takes IO21 away from the IR receiver, so the receiver is intentionally left disabled when the terminal owns that pin.
