## Merge layout

| File | Offset |
|---|---:|
| `bootloader_@0x0000.bin` | `0x000000` |
| `partitions_@0x8000.bin` | `0x008000` |
| `boot_app0_@0xE000.bin` | `0x00E000` |
| `firmware_@0x10000.bin` | `0x010000` |
| `littlefs_@0x210000.bin` | `0x210000` |

Gaps are filled with `0xFF`. The final image ends at `0x3F0000`, leaving the 64 KiB coredump partition untouched. The merge tool replaces Windows build-user path prefixes with equal-length `PUBLIC_BUILD_PATH` placeholders so release images do not expose local usernames; image size and offsets are unchanged. It then recalculates the ESP32 application checksum and appended SHA-256 validation digest.

## Verification commands

```sh
# Rebuild the merged image from the five parts
python tools/merge_webflasher.py

# Verify the existing merged image without changing it
python tools/merge_webflasher.py --check

# Check sizes, offsets, hashes, and the browser/target config-page agreement
python tools/verify_artifacts.py

# Run the browser/target config-page codec test directly
node ch32v003-firmware/test_config_page.mjs
```

When the ESP32 application and merged image are absent, `verify_artifacts.py` verifies the checked-in target artifacts and reports those two images as skipped. After a local build and merge, it verifies the complete ESP32 image as well.

## Hardware verification

For this board, the strongest end-to-end check is:

1. Program a Samsung address/command/protocol through the web page.
2. Press the corresponding target button.
3. Confirm `/rest/ir` or `/wsir` reports Samsung with the expected raw frame.
4. Confirm the matrix shows the expected `IR:...` message.

SWIO read-back alone is not an acceptable verification method on this hardware.
