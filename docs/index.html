The ESP32-C3 hosts the UI, bit-bangs SWIO on IO5, decodes IR on IO21, and renders received codes on the 5×5 NeoPixel matrix. The CH32V003 firmware only transmits IR; each of its three buttons can use NEC or Samsung independently.

SWIO checklist

  • Connect ESP32 IO5 / I²C SDA to CH32V003 PD1 / SWIO.
  • Use the onboard 10 kΩ SDA pull-up; no external resistor or board modification is required.
  • Connect common ground.
  • Do not use I²C and SWIO at the same time; both use IO5.
  • Press a remote button before Detect or Program.
  • The target stays reachable for six seconds after wake.

Target pins: SW1 PC4, SW2 PC2, SW3 PC1, IR output PA2 / TIM1_CH2N.

Power matters. Matrix updates plus WiFi bursts can exceed a weak USB supply. The firmware limits brightness and scrolls once, but a stable supply is still required.

Browser flash with Adafruit WebSerial

  1. Build WCH_WebLink_ALL_at_0x0.bin locally first.
  2. Open Adafruit WebSerial ESPTool in a Web Serial-capable browser.
  3. Connect to the ESP32-C3 USB serial port and use 921600 baud if available.
  4. Set offset 0x0, choose the merged image, and run the erase/program operation.

A full erase/program clears saved device configuration. If auto-reset fails, hold BOOT (Button A), tap RESET, release BOOT, and reconnect.

Command-line flash

python -m esptool --chip esp32c3 --port COM11 --baud 921600 \
  --before usb_reset --after hard_reset \
  write_flash 0x0 build_output/webflasher/WCH_WebLink_ALL_at_0x0.bin

For web-only changes, flash littlefs_@0x210000.bin at 0x210000. The application is at 0x10000.

Target programming: use the IR page for normal operation. The config page is at 0x08000800; the complete target image starts at 0x08000000 and is 2112 bytes.

IRC2 config page

The 64-byte page at 0x08000800 stores magic IRC2, three four-byte button records, and a little-endian checksum over the first 16 bytes. Each record is address, command, protocol, 0xFF. Target protocol values are 0=NEC and 1=Samsung.

Blank, corrupt, old IRC1, or unsupported-protocol pages fall back to factory NEC commands 152, 31, and 62 at address 0x00.

Verification: SWIO read-back is unreliable on this hardware. Verify target output with the Bear-Buddy receiver or an independent IR decoder.

Numeric /wsflash arguments are decimal.

#i;                       # chip info
#r;134219776;64;          # read config page
#w;134219776;64;          # write config page header
#w;134217728;2112;        # write complete target image header
#E;                       # whole-chip erase

/rest/ir exposes the last frame, receiver histogram, uptime, and reset reason. Common reset reasons: 6 task watchdog, 9 brownout, 4 panic.

Known limitations

SWIO reads

Reads can return shifted or corrupted bytes. Writes are usable, but read-back is not proof.

Standby

The target is unreachable while asleep. Wake it with a button press before an on-demand operation.

No USB console

The blocking USB CDC console is intentionally removed. Do not expect COM11 debug output.

Task watchdog

Long interrupt-masked writes can starve the idle task. Explicit watchdog feeding between blocks is still open.

IR scope

The receiver supports NEC, extended NEC, and Samsung only. Extended addresses do not fit the target's 8-bit field.

Power

NeoPixel plus WiFi bursts can brown out a weak USB port. Brightness and one-pass scrolling are mitigations.

Private by design

Not published. This repository is private and this documentation page has not been enabled through GitHub Pages.

No deployment Wi-Fi credentials are stored in current source, documentation, or checked-in binaries. The source uses generic setup placeholders, and ESP32 application/merged images are generated locally. Replace the placeholders before deployment and review repository history before any public release. The device has no authentication and should remain on a trusted local network.
